# Портфолио 1С-Разработчика (Расширение для 1С:Бухгалтерия 3.0)

Данный репозиторий содержит расширение конфигурации «1С:Бухгалтерия предприятия 3.0» (учебная версия), разработанное для демонстрации навыков разработчика 1С. Проект включает в себя аналитическую отчетность, механизмы контроля данных, массовые обработки и элементы интеграции.

**Стек и инструменты:** 1С:Предприятие 8.3, Управляемые формы, СКД (Система компоновки данных), HTTP-сервисы, JSON, Блокировки данных, Расширения типовой конфигурации (1С:Бухгалтерия).

## 2. Функциональные возможности

### 2.1. Аналитический отчет «Взаиморасчеты с контрагентами»
Отчет позволяет увидеть чистое сальдо (Дт - Кт) по всем счетам расчетов (60, 62, 76) в разрезе контрагентов.

*   **Реализация:** Используется виртуальная таблица `РегистрБухгалтерии.Хозрасчетный.ОстаткиИОбороты` с передачей массива видов субконто.

### 2.2. Контроль корректности проведения документов
Внедрена бизнес-логика, запрещающая проведение документа «Реализация товаров и услуг» с нулевыми или отрицательными значениями в табличной части.

*   **Реализация:** Использован обработчик расширения `&После("ОбработкаПроведения")`.
*   **UX:** Сообщение об ошибке через `Новый СообщениеПользователю` с привязкой к конкретной ячейке (`Товары[0].Цена`). При клике на сообщение курсор автоматически переводится в проблемную строку.

![Контроль проведения документа](docs/Price-0-warning.jpg)

### 2.3. Массовая обработка данных с блокировками
Утилита для массового добавления комментариев к контрагентам с отображением прогресса.

*   **Реализация:** Асинхронная обработка данных пачками через `ПодключитьОбработчикОжидания`. Это позволяет обновлять лог без зависания клиентской части.
*   **Безопасность:** Все записи выполняются в одной транзакции с использованием `БлокировкаДанных` в режиме `Исключительный`. Используется метод `УстановитьЗначение`, что предотвращает ошибки типов и точечно блокирует только изменяемый элемент.
*   **Таблицы:** После проведения транзакции можно увидеть таблицу с измененным реквизитом контрагента (комментарий).

### 2.4. Интеграция: HTTP-сервис и парсинг JSON
Создан HTTP-сервис, который принимает GET-запрос с параметром ИНН и возвращает JSON с информацией о контрагенте (наименование и сумма долга).

*   **Реализация:** Создана функция-обработчик в модуле HTTP-сервиса (к сожалению, не работает в учебной версии). Используется `ЗаписьJSON` для формирования ответа и `ЧтениеJSON` для демонстрации обратного парсинга в других обработках.
*   **Пример запроса:** `GET /api/contractor/{ИНН}`

## 3. Архитектурные решения

В ходе разработки применялись следующие паттерны и подходы:

1.  **Изоляция кода (Декомпозиция):** Массовая обработка разбита на независимые функции (`ПолучитьСсылкиДляОбработки`, `ЗаблокироватьДанныеДляОбработки`, `ВыполнитьМассовоеИзменение`), что соответствует принципу единственной ответственности (SRP).
2.  **Вынос утилит в общий модуль:** Логика форматирования и проверки шагов обработки вынесена в общий модуль `Расш_Утилиты` для повторного использования.
3.  **Безопасность расширений:** Все изменения выполнены исключительно через механизмы расширения (`&После`, `&Вместо`). Типовой код не изменялся, что гарантирует поддержку при обновлениях конфигурации.
4.  **Обработка ошибок:** Все транзакции обернуты в блоки `Попытка... Исключение` с откатом (`ОтменитьТранзакцию`) в случае сбоя.
